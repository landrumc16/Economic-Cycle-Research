# Version 6.2 release and rollback runbook

## Release conditions
1. Run the isolated `Version 6.2 Release Contracts` workflow and the full `Milestone 1 - Economic Data Acquisition and QA` workflow. Both must pass. A green isolated test is **not** approval to release.
2. Confirm the `Monthly Economic Cycle Assessment` artifact includes `weekly_release_acceptance.json`, all 16 V6.2 HTML pages, `v6_sector_report.json` (11 sectors), and `v62_release_manifest.json` from the **same** qualified run.
3. The manifest must show `version: 6.2`, a 40-character originating `build_commit`, an official `assessment_date`, an `observation_cutoff`, `research_gate.qualified: true`, and `promotion_outcome: NEW_QUALIFIED`.
4. Review the executive three-question homepage, research disclosures, source links, sector economic-versus-investment distinction, and no personalized recommendations.
5. Inspect at 360px, 768px and desktop; verify keyboard navigation, no horizontal overflow, and all eleven sector pages.
6. Merge approved PR into `main` only after the preceding checks. Wait for Pages deployment. Compare public `v62_release_manifest.json` byte-for-byte or as parsed JSON with the accepted artifact; verify public `index.html` equals `overview.html` and the manifest source commit matches the originating monthly artifact.
7. Record the exact test and deployment run IDs and live URL in the closeout. Do **not** claim completion from CI success alone.

## Stale or failed monthly data
A `STALE_RESEARCH_ONLY` or failed assessment must not be promoted as a new V6.2 report. The Pages publication workflow recovers the last accepted site when a replacement is unqualified and labels its manifest `PRESERVED_PREVIOUS`. Its `build_commit` and official assessment date remain unchanged. A missing or unverified previous site is a deployment blocker, not permission to publish an unqualified candidate.

## Rollback
If the live site fails acceptance, stop new promotion and restore the last verified qualified Pages bundle from the previous successful deployment artifact or revert the release commit on `main` and rerun the established Pages workflow. Verify the restored public pages, sector count, source dates and manifest. Do not edit an archived official assessment to make it appear current.

## Known limitations
This is descriptive general economic research, not certified predictive crash timing, investment performance forecasts, or personalized financial advice. Missing valuation and relative-return evidence must remain visibly insufficient. Commercial investment-related publication still requires separate legal review.
