# Economic Cycle Research — Version 6.2 Roadmap and Definition of Done

**Status:** Implementation in progress on `v6.2-development`; release gates remain unverified. Track work in PR #2.  
**Source of truth:** [Final Product Blueprint](FINAL_PRODUCT_BLUEPRINT.md) and [Product Delivery Roadmap](PRODUCT_DELIVERY_ROADMAP.md).  
**Baseline:** Existing Version 6.1 public site and its shared research pipeline.  
**Theme:** Make the current product understandable, traceable, legally cautious, and verifiably published. **No new forecasting model or parallel data pipeline.**

## What Version 6.2 delivers

A polished mobile-first public economic intelligence site where an everyday reader can understand the dated monthly assessment in three minutes, inspect its source evidence, explore all eleven sectors without mistaking research for personalized recommendations, and verify that the displayed report is the latest qualified publication. Advanced forecasting, new global coverage, paid features, AI agents, and individual security ratings are **outside V6.2**.

## Milestones (execute in this order, in substantial testable chunks)

### M0. Baseline and release provenance
- Verify whether live Pages currently serves the latest V6.1 bundle or a preserved prior version; record exact evidence and tested commit.
- Inventory existing public page generation, artifact schemas, CI and Pages workflows; reuse them rather than rebuild.
- Add a machine-readable release manifest with version, build commit, build time, official assessment date, observation cutoff, source-status summary, research gate, and explicit promotion outcome: **NEW_QUALIFIED**, **PRESERVED_PREVIOUS**, or **FAILED**. The manifest must reflect the actual deployed bundle, not merely the current workflow run.
- **Acceptance:** tests for successful promotion, stale preservation and failed publication; deployed manifest matches visible report and accepted source artifact.

### M1. Three-question executive homepage
- In order: **Where We Are**, **Where We're Heading**, **Where Investors Should Look**.
- Each section: concise plain-language conclusion or **Insufficient Evidence**, assessment/observation dates, key evidence, contrary evidence, uncertainty, and link to the exact supporting research.
- Clearly distinguish data refresh date from official monthly conclusion date; show what materially changed since the prior accepted assessment, or state that no comparable prior assessment exists.
- **Acceptance:** deterministic snapshots/tests for current, stale, missing, contradictory and revised observations; no invented stage, crash probability, investment rank or certainty.

### M2. Research navigation and provenance
- Mobile-first responsive navigation; clear hierarchy and readable typography at 360px, 768px and desktop widths.
- Collapsible research library linking economic indicators, historical episodes, competing explanations, sector research, methodology, revisions, and monthly archive.
- Source links must lead to real available evidence; label absent source details honestly instead of displaying dead links.
- **Acceptance:** all internal links and anchors resolve in the generated site; keyboard and screen-reader-friendly navigation; automated HTML smoke checks and documented manual visual inspection.

### M3. General investment research and compliance
- Maintain all eleven GICS sectors and existing evidence-gated economic-fit versus investment-fit distinction.
- Clearly label dated sources, assumptions, benchmark and limitations; retain **Insufficient Evidence** for missing qualified valuation, earnings or relative-return evidence.
- Add concise sitewide notice and prominent investment-page disclaimer: educational/general research, **not personalized financial advice**. No user-specific buy/sell/hold instructions, suitability profiles, personal allocations or guaranteed returns.
- Add tests to confirm disclaimers appear on homepage, sectors and all eleven sector pages, and prevent personalized recommendation language in generated guidance.
- **Acceptance:** eleven sector routes work; source/evidence rules pass; notice coverage verified. Legal review remains a separate gate before commercial investment-related launch; disclaimer alone is not a legal exemption.

### M4. Monthly assessment and publication reliability
- Preserve one official monthly assessment and existing data-refresh workflows; no competing weekly research engine.
- Connect release manifest and V6.2 site contract to existing regression, monthly-build and Pages-promotion workflows.
- Distinguish successful deployment of a **new** qualified report from successful preservation of an **older** report; never claim latest V6.2 is live solely because Actions is green.
- Failed builds must not overwrite accepted Pages content. Publish visible source freshness and last accepted assessment date.
- **Acceptance:** end-to-end generated-artifact checks, regression suite, actual Actions run IDs, published URL checks and exact manifest/build-commit verification.

### M5. Final QA, documentation and closeout
- Remove broken navigation, redundant pages/duplicate code and avoid unnecessary redesigns.
- Validate at mobile, tablet and desktop widths; inspect loading/readability, accessibility basics, no missing content and no console-breaking scripts.
- Update README, release notes, current limitations, runbook and rollback instructions.
- Record test outputs, successful workflow run IDs, Pages URLs, live manifest version, known data limitations and remaining future-roadmap items.
- **Acceptance:** all release gates below PASS with reproducible evidence; merge to main and publish without breaking the accepted baseline.

## Non-negotiable definition of FINISHED

**V6.2 is finished only when ALL of the following are demonstrated:**

1. **Product:** A new reader can find the three core answers, dates, uncertainty and research links on a phone without navigating through technical data first.
2. **Truthfulness:** No unsupported phase classification, crash probability, forecast, sector rating, performance claim or personal recommendation; missing evidence visibly fails closed.
3. **Research traceability:** Material conclusions reference actual dated supporting evidence, with provenance, contradictions and known limitations accessible.
4. **Sector coverage:** All eleven sector pages render, work, and distinguish economic exposure from investment valuation.
5. **Compliance-by-design:** General educational disclaimer appears across the site and prominently on investment surfaces; no individualized advice functionality. Counsel review is required before commercial launch, not represented as completed by software tests.
6. **Accessibility:** Tested at 360px, 768px and desktop, with functional keyboard navigation, readable contrast, sensible headings, and no horizontal page overflow.
7. **Automated quality:** All existing Python unit/regression tests plus V6.2 contract, link, publication-manifest and compliance tests pass in GitHub Actions.
8. **Release integrity:** Monthly assessment and Pages workflows complete successfully; live Pages serves the **new V6.2 bundle** verified against its manifest and build commit, not merely a preserved older version.
9. **Operational safety:** A simulated bad/stale update preserves the last accepted site and correctly reports preservation, not new publication.
10. **Closeout:** Main branch, release evidence, limitations, rollback steps and next-version backlog documented. No known release-blocking errors.

**Any failed gate means IN PROGRESS, not finished.** Missing predictive research is not a blocker when transparently disclosed; inventing it is.

## Explicit exclusions (do not let scope creep delay release)

No new global data acquisition program, autonomous AI agent, predictive crash probability, individual-stock recommendations, portfolio personalization, monetization, replacement of existing research pipelines, or new historical-vintage certification project. Those belong to later blueprint phases.

## Implementation rules

- Use Karpathy-style engineering: inspect first, simplest solution, small composable functions, reuse existing interfaces, tests alongside changes, no speculative abstraction.
- Work in coherent milestone-sized chunks; avoid one-file-at-a-time micro-iterations and repeated roadmap discussions.
- Preserve Version 6.1 as rollback baseline until V6.2 is fully verified live.
- Never silently rewrite archived official assessments.
- Escalate only genuinely consequential product, legal, access or cost decisions.

## Release report format

At closeout report **PASS/FAIL** for each of the ten gates, test workflow URLs, publication workflow URL, exact deployed manifest version/commit, live page checks, and any remaining evidence limitations. No completion claim without those artifacts.
